# gaussdb-etl-builder 技能改造设计

日期：2026-08-08
状态：已确认（方案 A）

## 1. 背景与目标

`gaussdb-etl-builder` 技能当前把数据分析需求变成 GaussDB ETL 作业（目标表 DDL + 清洗/装载 SQL）。执行中暴露以下问题：

1. **P0**：外挂知识文档、平台变量文档加载步骤很少使用，增加无谓交互。
2. **P0**：输出目录确认时机过早（目标表名到 P1 才确定），默认值不好定。
3. **P1**：目标表/临时表字段长度没有继承源表长度的强制规则，容易写短导致装载失败。
4. **P2**：步骤计划确认闸门不够硬；没有约束 CTE 使用，生成的 SQL 难调试、难维护。
5. **P3**：目标表 `CREATE TABLE` SQL 因平台无法直接导入而用不上，需要改为可导入平台的字段定义 Excel。

目标：简化和硬化 P0/P1/P2，把 P3 目标表产物从 SQL 改为 Excel，并让参考文档、测试用例与主体规则保持一致。

## 2. 整体流程与文件结构

### 2.1 改动后的四阶段流程

| 阶段 | 内容 | 变化 |
|---|---|---|
| P0 开场 | 复述需求、收集源表结构、确认 4 位数据区编码 | 删除「外挂知识文档」「外挂平台变量文档」两步；输出目录确认移到 P1 |
| P1 定目标表 | 推导目标表结构（含字段长度继承规则）、确认输出目录、停等确认 | 新增字段长度规则；新增输出目录确认 |
| P2 定步骤计划 | 规划完整 ETL 步骤（含临时表拆分 CTE）、强制详细计划确认闸门、停等确认 | 强化确认闸门；新增 CTE 铁律 |
| P3 生成产物落盘 | 目标表 → 生成 12 列字段定义 Excel；临时表/装载 → 生成可执行 SQL；写 plan.md | 目标表产物从 SQL 改为 Excel |

### 2.3 新增产物形态

每个需求输出目录 `./<含前缀全名>/etl/` 下会得到：

- `目标表字段定义_<全名>.xlsx` —— 目标表 12 列字段定义（直接导入平台）
- `step1_创建临时表xxx.sql` …… `stepN_装载.sql` —— 临时表与装载 SQL
- `plan.md` —— 执行计划

## 3. P0 开场（简化）

1. **复述需求**：一两句话复述需求给用户确认。
2. **收集源表结构**：索要建表语句或字段清单（表名、字段名、类型、注释）；记下每张表的字段、类型、长度；字段名不确定时宁问不猜。
3. **确认 4 位数据区编码**：推导 Schema = `<编码>_DATA`、表名前缀 = `<编码>_`，统一大写。

不再询问「知识文档/平台变量文档」，不再读取任何外挂文档。

## 4. P1 定目标表（确认闸门）

提出并停等确认：

- **目标表名**：schema 限定全名 `<编码>_DATA.<编码>_<业务名>`（如 `ABCD_DATA.ABCD_EXAM_TOP10_BY_SUBJECT`）。
- **字段清单**：名称、类型、中文注释；类型走 `supported-column-types.md` 白名单，标识符全大写。
- **字段长度继承规则（强制）**：
  - 目标表/临时表字段的长度不得小于对应源表字段的长度。
  - 若同一目标字段取值来自多个源表字段，取最大的源表字段长度。
  - 对 `VARCHAR(n)`/`CHAR(n)` 取长度 `n`；对 `NUMERIC(p,s)` 取 `p` 与 `s` 都取较大者。
  - 拿不准源表长度时主动问，不臆造。
- **确认输出目录**：默认 `./<含前缀全名>/etl/`（如 `./ABCD_EXAM_TOP10_BY_SUBJECT/etl/`），目录不存在就创建，用户可改。

确认前不进 P2。

## 5. P2 定步骤计划（强制确认闸门）

目标表确认后，规划完整 ETL 步骤并**强制输出详细计划，等用户逐项确认**后才可执行。

展示格式（每步含）：
- 序号、步骤名称
- 是否临时表（`is_temp_table`）
- 输出表（schema 限定全名，或临时表原名）
- 一句话描述：做什么、输入来自哪
- 涉及的字段与关联键

确认文案：
> "以上是完整 ETL 步骤计划，请逐项核对。确认无误后我才开始生成 SQL 与 Excel；需要调整请直接指出。"

**用户确认前不进入 P3。**

### 5.1 CTE 铁律

**铁律 1：优先临时表，少用 WITH**
除非需要递归 CTE，否则不要用 `WITH`（公用表表达式）定义中间结果；改为「建临时表」+「INSERT 装载」多步骤：

- 把一条 `INSERT ... WITH ... SELECT` 拆成多个步骤。
- 目的：SQL 可逐步调试、降低维护难度。

**铁律 2：用 WITH 必须建对应临时表**
若某步骤确实使用 `WITH`，则 CTE 中每个 CTE 变量名指向的临时表结构，必须同步用 `CREATE TEMPORARY TABLE` 创建出来（平台要求，否则作业执行失败）：

- 即 `WITH tmp AS (...)` 时，`tmp` 也要有真实的 `CREATE TEMPORARY TABLE tmp (...)`。
- 顺序铁律依然适用：先建后写。

### 5.2 步骤顺序铁律（保留）

所有临时表、目标表必须在其写入步骤之前创建。先建后写。

## 6. P3 生成产物并落盘

按 P2 确认的计划逐步生成，全部写入 P1 确认的输出目录。

### 6.1 目标表（is_temp_table=false）→ 字段定义 Excel

- 不再生成 `CREATE TABLE` SQL。
- 用新增脚本 `scripts/generate_field_excel.py` 生成 `.xlsx`。
- 文件名：`目标表字段定义_<含前缀全名>.xlsx`。
- **12 列表头**（从左到右）：`属性 | 英文名 | 中文名 | 数据类型 | 长度 | 精度 | 主键 | 分布键 | 分区键 | 是否允许空值 | 默认值 | 备注`。
- **各列填写规则**：
  - **属性**：默认不填；除非用户有特殊说明。
  - **英文名/中文名**：字段的英文标识（大写）与中文注释。
  - **数据类型**：白名单类型名（如 `VARCHAR`、`NUMERIC`），不带长度。
  - **长度/精度**：长度取继承规则后的值；精度对应 `NUMERIC(p,s)` 的 `s`。
  - **主键/分布键/分区键**：默认 `否`；主键字段同时为分布键与分区键。
  - **是否允许空值**：主键 → `否`；非主键字段 → `是`。
  - **默认值/备注**：默认值留空（或按需求）；备注写字段口径。
- 生成后展示路径与列内容，等用户确认 Excel 无误。

### 6.2 临时表 / 装载步骤 → SQL

- 临时表步骤：`CREATE TEMPORARY TABLE ...`（会话临时 schema，不加数据区前缀）。
- 装载步骤：`INSERT INTO <目标表全名> SELECT ...`，引用临时表用原名。
- 文件：`step<序号>_<安全名>.sql`，UTF-8。

### 6.3 plan.md

按 `plan-template.md`（含新增输出目录节）生成执行计划。

全部写完后汇报：`plan.md`、每步 SQL、目标表字段定义 Excel 的完整路径。

## 8. Evals 改动

- **删除** eval 3（平台变量增量）与 eval 4（知识文档复用）。
- **保留** eval 0/1/2 并同步描述（产物里目标表改成 Excel 而非 SQL）。
- **新增** 3 个用例：
  1. 字段长度继承：需求中目标字段取值来自多个源表，验证目标表字段长度 = MAX(源表长度)。
  2. CTE 铁律：验证生成的 SQL 默认用临时表拆分，不出现 `WITH`（除非递归）；若用 WITH，CTE 名有对应临时表。
  3. 产物形态：验证目标表生成 `.xlsx`（12 列表头正确）而非建表 SQL，临时表/装载仍是 SQL。

## 9. Excel 生成器脚本设计

### `scripts/generate_field_excel.py`

**用途**：把目标表字段定义生成 12 列 `.xlsx`，供平台直接导入。

**运行方式**：
- 由 skill 在 P3 阶段调用，输入为「字段定义 + 表名」的参数化数据。
- 依赖 `openpyxl`（skill 运行时先检查，缺失则提示安装或直接生成 CSV 备选）。

**调用形态（示例）**：
```bash
python scripts/generate_field_excel.py \
  --output "目标表字段定义_ABCD_EXAM_TOP10_BY_SUBJECT.xlsx" \
  --table "ABCD_EXAM_TOP10_BY_SUBJECT" \
  --fields '[{"english":"EXAM_NAME","chinese":"考试名称","type":"VARCHAR","length":100,"precision":null,"is_pk":false,"is_dist_key":false,"is_part_key":false,"nullable":"是","default":null,"remark":"..."}, ...]'
```

**脚本职责**：
1. 解析传入的 JSON 字段定义。
2. 生成 12 列表头：`属性 | 英文名 | 中文名 | 数据类型 | 长度 | 精度 | 主键 | 分布键 | 分区键 | 是否允许空值 | 默认值 | 备注`。
3. 每行填一个字段；属性列默认不填（除非调用方传入 `attribute`）。
4. 主键字段 → 主键/分布键/分区键列 = `是`，允许空值 = `否`。
5. 输出 UTF-8 编码的 `.xlsx`（openpyxl 默认，另存 CSV 时用 UTF-8-BOM 便于 Excel 打开）。

**健壮性**：
- 表名/文件名安全化（非法字符替换，超长截断）。
- 无字段时警告。
- 数据校验：类型必须在白名单内（脚本内嵌白名单副本），非法类型报错并中止。

**测试方式**：脚本可用临时输入跑一遍，检查 12 列表头、字段行、主键行三列=`是`、属性列空等。

## 10. 依赖

- 新增脚本依赖 `openpyxl`；无其他新依赖。

## 11. 验收标准

1. P0 不再询问外挂文档，不再读取知识/平台变量文档。
2. P1 生成的目标表字段长度满足长度继承规则。
3. P1 输出目录默认为 `./<含前缀全名>/etl/`。
4. P2 强制详细计划确认，未经确认不进入 P3。
5. P2 生成的 SQL 默认用临时表拆分；不使用 WITH 或使用 WITH 时 CTE 名有对应临时表。
6. P3 目标表生成 12 列字段定义 `.xlsx`（属性列默认不填、主键列三列=`是`），临时表与装载仍为 SQL。
7. evals 覆盖以上新规则，旧的依赖外挂文档用例已移除。
